Ponyo Site Blueprint

One page on how the site is built, hosted and run. Update it whenever a service, page, data store, backup or release step changes.

Snapshot: 27 November 2026 Site: byponyo.com Maintained by: Nena Sources: code repository and production checks reported 27 November 2026

Production status · 27 November 2026: The storefront and API are live on AWS Lightsail Tokyo via Docker Compose; HTTPS and the www redirect were smoke-tested. Supabase Tokyo is the production database. Releases are manual; no automatic deployment or persistent staging environment is documented. Stripe remains off. A manual database dump was validated, but scheduled backups and a restore test are not verified. See the production operations runbook.

Where we are today

  • Custom-coded shop, not a ready-made shop system. Next.js pages, a FastAPI back end and a PostgreSQL database, all in one GitHub repository.
  • Live. byponyo.com and the API are served over HTTPS from AWS Lightsail Tokyo. The www hostname redirects to the main domain.
  • Switched on: browsing, product reservations and interest sign-ups (no payment), newsletter, contact form, maker applications, Admin and Supplier portals.
  • Built but switched off: cart, checkout and Stripe payments, customer accounts, product reviews, the journal.

7How a change reaches the live site

Code changes (design, features, fixes)

  1. Developer changes the code and tests it on the local copy.
  2. Code is pushed to GitHub; back-end tests run automatically.
  3. GitHub Actions runs checks; it does not publish to production.
  4. An authorized operator connects to Lightsail by SSH, pulls the reviewed commit, and rebuilds/restarts the Docker Compose services.

Content changes (products)

  1. An admin logs in to the Admin Portal.
  2. Publishes or unpublishes a product, or changes its category or reservation settings.
  3. The change is visible immediately. No code release is needed.

Test copy separate from live? Local development is separate, but there is no permanent staging site/database. Who can publish? Code: authorized GitHub contributors plus Lightsail access; named release owner TBC. Products: accounts with the admin role.

8How a product gets added today

  1. Supplier submits the product draft, details and photos through the Supplier Portal.
  2. Admin reviews and approves or rejects the submission. Approval creates an unpublished product with its default variant, supplier offer and inventory.
  3. Admin publishes the product after required Japanese and Korean translations are available.
  4. The product can appear for reservation or interest sign-up. Checkout and payment remain off.

A new maker first applies at /for-makers, is accepted, completes onboarding and receives supplier access. Supplier submissions stay unpublished until Admin approval and a separate publication action. Retail price is approved wholesale cost +20%.

How long does one take? Not measured yet TBC. Time one supplier submission through review, translation and publication.
